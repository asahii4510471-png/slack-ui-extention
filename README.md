# Slack UI 拡張

ブラウザ版 Slack にヘッダー用のボタン4個と、メッセージ操作用の「タスクに追加」を表示する Manifest V3 拡張です。v0.2.0 は集中モード、ブラウザで開く、メンション分離に対応します。

## Chrome で読み込む

1. このリポジトリをダウンロードして展開する。
2. Chrome で `chrome://extensions` を開き、右上の「デベロッパー モード」を有効にする。
3. 「パッケージ化されていない拡張機能を読み込む」で **extension フォルダ**（manifest.json のある階層）を選ぶ。
4. ログイン済みの Slack タブを再読み込みする。ビルドと依存パッケージのインストールは不要。

## 実機確認の記録

2026-11-18、ユーザーの Windows Chrome と Slack_addin_test で v0.1.0 のヘッダー4ボタン、通常投稿のホバー操作、各スタブ通知、チャンネル切替・スレッド開閉後の表示維持を確認済み。オプションの ON/OFF は手動確認待ち。

## v0.2.0 の実装と手動確認

上の手順で更新し、拡張管理でバージョン 0.2.0 を確認して Slack_addin_test を再読み込みする。

- **集中モード**。チャンネルの「集中モード」を押す。上部ナビゲーション、左レール、チャンネルサイドバーが消え、本文が広がることを確認する。スレッドを開閉し、リロード後もモードが続き、同じボタンで戻ることを確認する。html の状態クラスと CSS で表示を切り替える。チャンネルヘッダーに解除ボタンを残す。
- **ブラウザで開く**。既定は OFF。ボタンを押して ON にし、app.slack.com 上の既存の slack:// リンクをクリックする。capture 段階で既定動作を止め、クエリ値に HTTPS の app.slack.com URL があれば同じタブで開く。なければ「アプリ起動をブロックしました」と表示する。通常の HTTPS リンクも試す。別ドメインの着地ページやスクリプトから直接行うアプリ起動は検出対象外。
- **状態と設定**。上記2モードの状態は機能の表示設定と別のキーで chrome.storage.local に保存する。オプションで各機能を無効化して、ボタンと効果が消えること、再有効化で保存した状態に戻ることを確認する。
- **メンション分離**。Slack の「アクティビティ」を開くとフィルタが表示される。各分類を選んで該当する項目のみ表示され、「すべて」で復帰することを確認する。ヘッダーボタンはフィルタにフォーカスし、他画面では場所を案内する。分類可能な項目がない初期画面には「すべて」のみを表示する。
- **分類の根拠**。実画面で activity-item-container の activity-item-message 内に、個人宛のリンクと data-stringify-type="mention"、data-member-id を確認した。本人のフィードなので個人宛メンションは原則本人宛とみなす。識別したチップの表示文字が @channel / @here / @everyone なら全体、data-usergroup-id または data-stringify-type="usergroup" があればチーム、data-member-id があれば自分宛の順で判定する。識別できない項目は「すべて」に残す。チーム・全体の信号は実例での確認待ち。変更するのはローカルの表示のみ。
- **既存機能**。「チャンネルグループ」と通常投稿の「タスクに追加」は従来の未実装通知を表示する。

## 機能を追加する

1. `extension/features/` に `<id>.js` を作る。半角英小文字・数字・ハイフンの一意な ID を使う。例として次の定義を `bookmark-message.js` に保存する。

   ```js
   export default {
     id: 'bookmark-message',
     title: 'あとで読む',
     icon: '<svg viewBox="0 0 24 24" aria-hidden="true"><path fill="currentColor" d="M5 3h14v18l-7-4-7 4z"/></svg>',
     location: 'message',
     onClick(ctx) { ctx.toast('未実装：あとで読む'); }
   };
   ```

2. `extension/registry.js` の `ids` 配列に `'bookmark-message',` を1行追加する。設定画面にも自動で現れる。アイコンには同梱の静的 SVG を使う。
3. `extension/manifest.json` の version を上げる。Chrome の拡張管理で更新してから Slack を再読み込みする。

ヘッダーの handler には `ctx.toast(text)`、メッセージの handler にはさらに `ctx.text` と `ctx.permalink` を渡す。クリック時に対象行から読み取り、取得できない項目は個別に null になる。保存対象は機能の有効状態とモード設定。スクリプトはすべて拡張に同梱する。拡張から外部への通信は行わない。

## テスト

リポジトリ直下で Node.js 20 以降の `node --test` を実行する。登録順、個別の読み込み失敗、stub の通知、設定変更を検証する。

## Chrome ウェブストアで限定公開する

1. 開発者アカウントを登録し、extension フォルダの**中身**を ZIP 化する。ZIP の直下に manifest.json を置く。
2. デベロッパー ダッシュボードで新しいアイテムを追加し、ZIP をアップロードする。掲載用の説明、アイコン、スクリーンショット、プライバシー申告、権限の用途などの必須項目を入力する。
3. 配布設定の公開範囲を **Unlisted（限定公開）** にして審査に提出する。公開後は掲載 URL を知る人がインストールできる。[Chrome 公式の配布設定](https://developer.chrome.com/docs/webstore/cws-dashboard-distribution)
